# Project brief — Magnolia Institute Resource Library

| Field | Entry |
|---|---|
| Problem | People looking for care, legal help, food, housing, or crisis support have to hunt across sites they do not trust. Earlier community-resource work existed; it was not a living, verified directory. |
| Users | Public visitors in South Carolina and the Lowcountry. Reviewers inside Midnight Magnolia. Organizations suggesting a listing. |
| Public boundary | Organization name, program, description, website, public phone, eligibility summary, accessibility summary, location, last verification date, status badge. |
| Internal boundary | Reviewer notes, duplicate flags, change history, next-review dates, dashboard counts. |
| Restricted data | Submitter contact, safety notes, reviewer identity, unpublished submissions. |
| MVP features | Six-category taxonomy. Postgres schema with verification and change log. About 20 verified public records. Suggest-a-resource stays pending. No public directory UI in weeks 1–2. |
| Owner | Latisha Vincent-Waters |
| Success signal | A reviewer can read the ERD, the verification policy, and 20 records with documented provenance — and know what is public versus held back. |
| Out of scope | Weeks 3–4 directory/search UI. Paid listings. Marketing capture from search. Merging Institute rows into genealogy or Press contacts. |
| Status | Weeks 1–2 in progress (2026-09-01). Planned, not launched. |
| Case-study spine | Challenge → Role → Architecture → Build → Governance → Outcome. Outcome stays **in development** until the public directory ships. |
