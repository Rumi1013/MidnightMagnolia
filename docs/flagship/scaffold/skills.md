# skills.md

## Purpose
This file defines the capabilities the repository is intended to demonstrate, the artifacts that prove each capability, and the constraints governing their use.

## Core capability map

### 1. Information governance and records management
**Capabilities:** classification, retention, legal hold, disposition, digitization, access boundaries, version control, and change history.
**Evidence:** classification matrix, retention schedule, records register, legal-hold procedure, disposition log, migration checklist, and access-role map.

### 2. Relational database design
**Capabilities:** stable identifiers, normalized entities, relationships, source tracking, assertions, status models, and audit fields.
**Evidence:** SQL schemas, ERDs, data dictionaries, constraints, sanitized seed data, and migration notes.

### 3. Resource-directory operations
**Capabilities:** taxonomy, search/filter requirements, submission intake, duplicate review, verification, scheduled reverification, publication, update, and archive.
**Evidence:** Institute schema, vetting SOP, verification queue, sample records, test cases, and dashboard specification.

### 4. Archival and genealogy research systems
**Capabilities:** people and relationship modeling, place and source management, documented facts versus hypotheses, contribution review, research logs, privacy controls, and client request intake.
**Evidence:** Roots schema, metadata dictionary, research-log template, evidence-status rules, privacy policy, sample records, and review tests.

### 5. CRM and event operations
**Capabilities:** event registration, contact deduplication, consent, segmentation, confirmations, reminders, attendance states, follow-up, automation logging, retries, and incident resolution.
**Evidence:** Press schema, workflow specification, payload examples, automation health metrics, issue-log template, and failure tests.

### 6. API, webhook, and automation design
**Capabilities:** payload validation, system handoff, idempotency, error capture, safe retry, escalation, logging, and recovery documentation.
**Evidence:** API contract, webhook sample, automation run schema, issue records, and test fixtures.

### 7. RAG and AI-project structure
**Capabilities:** modular ingestion, chunking, embeddings, vector storage, retrieval, prompt management, model calls, configuration, tests, logs, utilities, and evaluation.
**Evidence:** separated folders, prompt registry, index manifest, fixed evaluation questions, expected-source fixtures, and synchronization notes.

### 8. Program operations and onboarding
**Capabilities:** role-owned SOPs, triggers, decision points, outputs, escalation, review cadence, quick references, and onboarding milestones.
**Evidence:** SOP template, onboarding checklist, governance cadence, and operations dashboard fields.

### 9. Communications governance
**Capabilities:** audience-first writing, consistent terminology, accuracy review, plain-language editing, leadership approval, event coordination, measurement, and crisis routing.
**Evidence:** style guide, messaging brief, run-of-show, debrief, approval matrix, and crisis decision tree.

### 10. Portfolio and career evidence
**Capabilities:** challenge-to-outcome case studies, inspectable architecture, sanitized proof, claim-to-evidence mapping, job-fit analysis, and evidence-based application writing.
**Evidence:** case-study templates, portfolio evidence register, resume proof bank, role-fit matrix, and application checklist.

## Skill execution rule
No capability may be claimed as demonstrated until the corresponding working artifact, documentation, and sanitized technical evidence exist. Historical work and modern reconstruction must be labeled accurately.
