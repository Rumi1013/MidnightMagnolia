# System overview

The ecosystem uses a shared design language and reusable infrastructure while maintaining purpose-based data boundaries.

- Public website: directories, archive search, event pages, and forms.
- Application/API: validation, access control, business rules, API endpoints, and webhook handling.
- Database: structured records with separate project schemas or explicit permissions.
- Automation: notifications, scheduled review, handoffs, retries, and issue logging.
- Operations dashboard: pending work, verification queues, moderation, event operations, and automation health.
- Documentation: ERDs, dictionaries, SOPs, privacy rules, workflow maps, and change history.
- Portfolio layer: sanitized case studies, screenshots, demos, architecture, and repository evidence.
